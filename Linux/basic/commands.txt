# grep command options

grep "error" logfile.log     # search for "error" in logfile.log
grep -i "hello" file.txt     # case insensitive

| Option   | Meaning                                | Explanation & Use Case                                                                                                | Example                                                                  |
| -------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| -i       | Case-insensitive search                | Ignores uppercase/lowercase differences. Useful when you don’t know the exact case of the word.                       | grep -i "hello" file.txt → matches Hello, HELLO, hello.                  |
| -n       | Show line numbers                      | Prints the line number along with the matching line, helpful for locating matches.                                    | grep -n "error" logfile.log → output like 23:error found.                |
| -v       | Invert match (show non-matching lines) | Shows all lines that do not match the given pattern. Great for filtering out unwanted data.                           | grep -v "success" file.txt → shows all lines without “success”.          |
| -c       | Count number of matches                | Displays only the number of matching lines, not the content. Useful for stats.                                        | grep -c "fail" file.txt → outputs 5 if 5 lines match.                    |
| -l       | Show filenames with matches            | Prints only filenames that contain matches, not the matching lines. Very useful when searching across multiple files. | grep -l "TODO" *.java → prints file names with “TODO”.                   |
| -r       | Recursive search in directories        | Searches inside all files under the given directory (recursively). Great for searching code/projects.                 | grep -r "main" ./src → finds all occurrences of main in src/.            |
| -w       | Match whole words only                 | Ensures only exact words match. Without -w, partial matches also appear.                                              | grep -w "cat" file.txt → matches cat, not category or educate.           |
| -o       | Print only the matching part           | Instead of printing whole line, prints just the matched word/pattern.                                                 | grep -o "foo[0-9]" file.txt → prints foo1, foo2, etc.                    |
| -A n     | Show n lines After match               | Useful to see context after a match (like error logs).                                                                | grep -A 2 "error" logfile.log → prints matched line + 2 lines after.     |
| -B n     | Show n lines Before match              | Useful to see what happened before an error/warning.                                                                  | grep -B 2 "error" logfile.log → prints matched line + 2 lines before.    |
| -C n     | Show n lines Around match              | Shows context both before and after the match.                                                                        | grep -C 3 "error" logfile.log → prints match + 3 lines before & after.   |

# Examples:
grep "error" logfile.log     # search for "error" in logfile.log
grep -i "hello" file.txt     # case insensitive
grep -n "error" logfile.log   # show line numbers with matches
grep -v "success" file.txt    # show lines that do NOT contain "success"
grep -c "fail" file.txt       # count number of lines containing "fail"
grep -l "TODO" *.java         # list filenames containing "TODO"
grep -r "main" ./src          # recursively search for "main" in src/
grep -w "cat" file.txt        # match whole word "cat" only
grep -o "foo[0-9]" file.txt   # print only matching parts like foo1, foo2
grep -A 2 "error" logfile.log  # show 2 lines after each "error" match
grep -B 2 "error" logfile.log  # show 2 lines before each "error" match
grep -C 3 "error" logfile.log  # show 3 lines before and after each "error" match

The touch command in Linux is mainly used for two things:
If the file doesn’t exist, touch will create it.
If the file already exists, touch will update its access and modification timestamps to the current time.
$ touch myfile.txt                  # update to current timestamp
$ touch -t 202410011200 myfile.txt  # set specific timestamp (YYYYMMDDhhmm)
$ touch -a myfile.txt               # change only access time
$ touch -m myfile.txt               # change only modification time

$ touch file1 file2 file3 → create multiple files at once.
$ touch -c file.txt → don’t create the file, only change timestamp if it exists.
$ touch -t 202509171200 file.txt → set a custom timestamp (YYYYMMDDhhmm).

# display content with pages
more and less commands

more filename
# view file page by page (forward only)
# Shows the file one screen/page at a time.
# You can scroll forward, but not backward (very limited compared to less).

Common keys in more:
Space → Next page (scroll one screen down).
Enter → Next line.
q → Quit.
f → Forward one screen (same as space).

less filename
# view file page by page (forward and backward)
# less is more advanced than more, allows backward navigation
# less supports searching within the file using /pattern
# Press q to quit less

Common keys in less:

Space → Next page.
Enter → Next line.
f → Forward one page (same as space).
b → Backward one page.
↑ / ↓ arrows → Move one line up/down.
g → Go to beginning of file.
G → Go to end of file.
type to search the work -> /word → Search forward for “word”.
Press n → next match.
Press N → previous match.
q → Quit.

$ cat /var/log/syslog
This will flood the terminal 
better use more or less
$ cat /var/log/syslog | more
$ cat /var/log/syslog | less

or directly

$ more /var/log/syslog
$ less /var/log/syslog

more = basic pager (forward only). Displays the file page by page.
less = advanced pager (forward, backward, search, navigation).

# translate characters
tr command -> translate byte by byte or character by character
The tr command works on standard input → standard output, character by character.

-d option: delete characters
-s option: squeeze characters (replace multiple with single)

$ echo "hello world" | tr 'a-z' 'A-Z'
Output: HELLO WORLD

$ echo "apple banana cherry" | tr ' ' '\n'
apple
banana
cherry

$ echo "My phone number is 12345" | tr -d '0-9'
Output: My phone number is

$ echo "Hello     World   !!!" | tr -s ' '
Output: Hello World !!!

$ echo -e "Line1\nLine2\nLine3" | tr -d '\n'
Output: Line1Line2Line3

$ echo "abc123xyz789" | tr -cd '0-9'. ## keep only digits
Output: 123789

## comparison commands

cmp  # diffeneciate character by charatctewr or byte by byte

Hello
World
Linux

File file2.txt:
Hello
Word
Linux OS

diff file1 file2
# Output:
2c2
< World
---
> Word
3c3
< Linux
---
> Linux OS

Explanation:

Line 2: World (in file1) vs Word (in file2).
Line 3: Linux vs Linux OS.

2c2 → line 2 in file1 should be changed (c) to match line 2 in file2.
< World → line in file1.
> Word → line in file2.
--- → separator between the two.

3c3
< Linux
---
> Linux OS
# 3c3 → line 3 in file1 should be changed (c) to match line 3 in file2.
< Linux → line in file1.
> Linux OS → line in file2.
--- → separator between the two.

# uniq command: filter out duplicate lines (often used with sort)
# Common options:
#   -c : count occurrences of each line
#   -d : show only duplicate lines
#   -u : show only unique lines 
# Note: uniq only removes adjacent duplicate lines, so usually you sort the file first.
# Examples:
cat > sample.txt
apple
banana
apple
orange
banana
apple
banana
orange
orange
$ sort sample.txt | uniq -c  # count occurrences of each line
# Output:
# 3 apple
# 3 banana
# 3 orange

$ uniq sample.txt  # remove adjacent duplicates (no count)
# Output:
apple
banana
apple
orange
banana
apple
banana
orange
orange

# To effectively use uniq, sort the file first:
$ sort sample.txt | uniq
# Output:
apple
banana
orange  


uniq command
uniq -u sample.txt # show only unique lines
uniq -d sample.txt # show only duplicate lines

filter commands: 
sed # stream editor for filtering and transforming text
$ sed 's/old/new/g' file.txt  # replace 'old' with 'new' globally in file.txt

grep # search for patterns in files
$ grep 'pattern' file.txt  # print lines matching 'pattern' in file.txt

pipe # send output of one command as input to another
$ command1 | command2  # use | to pipe output from command1 to command2

find # search for files and directories based on criteria
$ find /path -name "filename"  # find files named 'filename' in /path
$ find /path -type f -size +10M  # find files larger than 10MB in /path

permissions commands:
chmod # change file permissions

rwx for user, group, others
r=4, w=2, x=1
category u=user, g=group, o=others, a=all
# Numeric method: chmod 755 file.sh (rwxr-xr-x)
# Symbolic method: chmod u+x file.sh (add execute for user)

# Examples:
chmod 755 script.sh  # rwxr-xr-x
chmod 644 file.txt   # rw-r--r--
chmod u+x script.sh  # add execute permission for user
chmod g-w file.txt   # remove write permission for group
chmod o-r file.txt   # remove read permission for others
chmod a+x script.sh  # add execute permission for all (user, group, others)
chmod u=rwx,g=rx,o=r file.txt  # set specific permissions
